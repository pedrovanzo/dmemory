# Token weight is not evenly distributed across a workflow

AI-assisted development is expensive to *formulate* — thinking about, formulating,
coming up with concepts, ideas, even code-based solutions — but comparatively
cheap to *reproduce* once that thinking is done.

During any given workflow, this is a delicate and real distinction worth
weighing in how work is structured. Token-heavy cost sits in the planning
phase: defining, architecting, problem-solving, before touching code.
Execution itself may bring volume, but it behaves almost like a repetition
exercise for the LLM — the hard thinking already happened, and the remaining
cost is moving pieces across the board, not manufacturing the board itself.

A (non-literal) illustration: 5 tokens burned per unit of planning work vs.
2 tokens burned per unit of execution work. The numbers are not meant to be
taken literally — they represent proportion, not measurement.

A supporting example: Matt Pocock's workflow barely mentions token cost,
because his workflow shapes token usage this way by construction — heavy
thinking up front, cheap mechanical execution after.
